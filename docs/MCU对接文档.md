## 2. 帧格式

所有命令双向使用统一帧格式：

```
+--------+--------+--------+--------+-----+----------+--------+
| HEAD   | HEAD   | LEN    | CMD    | SEQ | PAYLOAD  | CRC8   |
| 0xAA   | 0x55   | 1字节  | 1字节  | 1字节| LEN字节  | 1字节  |
+--------+--------+--------+--------+-----+----------+--------+
```

| 字段 | 说明 |
|------|------|
| HEAD | 固定 `0xAA 0x55` |
| LEN | PAYLOAD 的字节数（**不含**头/CMD/SEQ/CRC），最大 128 |
| CMD | 命令字，见第 4 节 |
| SEQ | 事务序号。请求方自增；**应答/结果帧回用请求帧的 SEQ** |
| PAYLOAD | 数据段，可为空（LEN=0） |
| CRC8 | 对 HEAD~PAYLOAD **全部字节**（即 CRC 之前的所有字节）计算 |

整帧长度 = `6 + LEN`。

**接收解析要点**：
- 在字节流中搜索 `0xAA 0x55` 帧头；找不到帧头时清空缓冲区
- LEN > 128 视为非法，丢弃该帧头后继续搜索
- 数据不足整帧时保留缓冲区等待后续字节（串口分包到达是常态）
- CRC 校验失败直接丢弃整帧

## 5. 各命令详细说明

### 5.1 心跳

**MCU → 视觉：HB_M (0x41)**

- 视觉端只刷新"最后收到时间"，**不解析 PAYLOAD 内容**，可发任意内容（建议 3 字节 `[state, err, rsv]` 与视觉端心跳对齐）
- 视觉端 1.5s 未收到 HB_M 判定链路断开（屏幕 LINK 变 DISC）

**视觉 → MCU：HB_V (0x01)**

- 周期 250ms，PAYLOAD 固定 3 字节：

| 字节 | 含义 |
|------|------|
| [0] | 视觉端状态码（见 9.1） |
| [1] | 错误码（当前固定 0） |
| [2] | 保留（固定 0） |

- SEQ 为视觉端内部自增序号
- 扫描/显示等阻塞操作期间心跳可能延迟，**最坏情况约 1s**，MCU 侧超时阈值建议 ≥ 2s

### 5.2 SYS_START 系统启动 (0x42)

**请求 PAYLOAD（2 字节）**：

| 字节 | 含义 |
|------|------|
| [0] | mode 工作模式（当前未使用，填 0x01） |
| [1] | 协议版本号，必须 = 0x02 |

**应答 0xC2 PAYLOAD**：

| 字节 | 含义 |
|------|------|
| [0] | 结果码：0x00=成功，0x02=协议版本不匹配 |
| [1] | 视觉端协议版本号（0x02） |

- 成功后视觉端进入 **READY** 状态
- 版本不匹配时视觉端拒绝进入 READY

### 5.3 SCAN_REQ 扫描请求 (0x43)

**请求 PAYLOAD（2 字节）**：

| 字节 | 含义 |
|------|------|
| [0] | reason 扫描原因（视觉端当前不区分，建议填 0x01） |
| [1] | 保留（填 0x00） |

**响应：SCAN_RESULT (0x02)**，检测完成后**主动推送**（约 0.6~1.0s 后，见第 10 节）。

**SCAN_RESULT PAYLOAD 结构**：

| 字节 | 含义 |
|------|------|
| [0] | reason（当前**固定回填 0x01**，不回显请求值） |
| [1] | total 物料总数（0~255） |
| [2] | batch 批次号（从 0 开始） |
| [3] | count 本批物料数（≤12） |
| [4...] | count × 10 字节的物料数据 |

**单个物料（10 字节，小端序）**：

| 偏移 | 类型 | 含义 |
|------|------|------|
| 0 | u8 | 形状 ID（见 8.1） |
| 1 | u8 | 颜色 ID（见 8.2） |
| 2 | u8 | pickable：1=可抓取，0=不可抓（异形固定为 0） |
| 3 | u8 | 保留（0x00） |
| 4~5 | i16 LE | 机械坐标 X，单位 **0.1mm** |
| 6~7 | i16 LE | 机械坐标 Y，单位 **0.1mm** |
| 8~9 | u16 LE | 角度：0~359 有效；**0xFFFF=无方向**（当前视觉端固定发 0xFFFF） |

**分批规则**：每批最多 12 件，超过自动分多帧发送，批间间隔 50ms。

**空结果**：一件都没检测到时，发送 `total=0, batch=0, count=0` 的 4 字节 PAYLOAD 帧（**不会不发**）。

MCU 收到 SCAN_RESULT **无需应答**。

### 5.4 PICK_REPORT 分拣上报 (0x44)

MCU 每完成一次抓取，向视觉端上报，用于屏幕显示与记录。

**请求 PAYLOAD（6 字节）**：

| 字节 | 类型 | 含义 |
|------|------|------|
| [0] | u8 | 分拣序号（从 1 开始） |
| [1] | u8 | 形状 ID |
| [2] | u8 | 颜色 ID |
| [3] | u8 | 结果：0x00=成功，非 0=失败 |
| [4~5] | u16 LE | 累计成功数 |

**应答 0xC4 PAYLOAD（1 字节）**：结果码 0x00。

- 视觉端收到后屏幕显示四要素约 500ms，**然后才回应答**
- MCU 侧等待 0xC4 的超时建议 ≥ 1s

### 5.5 PING 链路测试 (0x4F)

- PAYLOAD 任意（建议 4 字节特征码）
- 应答 0xCF 原样回显 PAYLOAD

### 5.6 RECHECK_REQ 复核请求 (0x45)

MCU 发送期望的物料清单，视觉端**重新执行一次完整扫描**（与 SCAN_REQ 相同流程），将实际检测结果与期望清单比对后回复。

**请求 PAYLOAD**：

| 字节 | 含义 |
|------|------|
| [0] | count 期望物料数量 |
| [1+2k] | 第 k 件物料的形状 ID |
| [2+2k] | 第 k 件物料的颜色 ID |

**响应：RECHECK_RESULT (0x03)**，复核完成后主动推送（耗时同扫描，约 0.6~1.0s）。

**RECHECK_RESULT PAYLOAD**：

| 字节 | 含义 |
|------|------|
| [0] | match：0x01=与期望清单一致，0x00=不一致 |
| [1] | count 实际检测到的物料数 |
| [2...] | count × 10 字节的物料数据（结构同 SCAN_RESULT，见 5.3） |

**比对规则**：仅比较 (形状ID, 颜色ID) 构成的**多重集合**是否完全一致（数量、形状、颜色都对得上即 match=1），**不比较坐标**。

> ⚠️ 颜色未识别的物料不参与比对也不包含在物料数据中，会导致 match=0。

### 5.7 DUMP_REPORT 倾倒完成 (0x47)

**请求 PAYLOAD**：保留，当前不解析（建议发 0 字节）。

**应答 0xC7 PAYLOAD（1 字节）**：结果码 0x00（**立即应答**）。

视觉端收到后屏幕短暂显示 "Dump Done"。

### 5.8 FINISH 比赛结束 (0x48)

**请求 PAYLOAD（5 字节）**：

| 字节 | 类型 | 含义 |
|------|------|------|
| [0~1] | u16 LE | total_ok 累计成功数 |
| [2] | u8 | total 物料总数 |
| [3~4] | u16 LE | elapsed_s 总用时（秒） |

**应答 0xC8 PAYLOAD（1 字节）**：结果码 0x00（**立即应答**）。

视觉端收到后进入 FINISHED 状态（心跳状态码变为 7），屏幕显示成绩总结约 2s。

## 6. 完整业务流程

```
上电
 │
 │◄──────── 双向心跳 (MCU:0x41 / 视觉:0x01@250ms) ────────►│
 │
 ▼
MCU ── SYS_START (0x42, ver=0x02) ──► 视觉
MCU ◄─ ACK (0xC2, R_OK, ver=0x02) ── 视觉    [视觉进入 READY]
 │
 ▼
[托盘到位后] 
MCU ── SCAN_REQ (0x43) ─────────────► 视觉
                                      │ 视觉执行检测 (~0.6~1.0s)
                                      │ 期间屏幕显示 Scanning...
MCU ◄─ SCAN_RESULT (0x02, 全部物料) ── 视觉   [视觉回到 READY]
 │
 ▼
MCU 根据物料清单自行规划抓取（视觉端不参与决策）
 │
 ▼ (每抓完一件)
MCU ── PICK_REPORT (0x44) ──────────► 视觉
                                      │ 屏幕显示四要素 500ms
MCU ◄─ ACK (0xC4) ─────────────────── 视觉
 │
 ▼
重复 PICK_REPORT 直至全部抓完 → 回到 SCAN_REQ 开始下一轮
```

**关键认知**：
- 扫描结果是**一次性全量推送**的，视觉端**不留存**检测结果供查询
- 没有"按形状颜色查询"类指令，抓取规划完全由 MCU 负责
- PICK_REPORT 是 MCU → 视觉的单向告知（用于屏幕展示），不是查询

## 7. 坐标系统

### 7.1 坐标变换及原点平移

模型检测得到的 ROI 归一化坐标 `(norm_x, norm_y)` ∈ [0,1]，发送前按以下步骤转换
为实际机械坐标。坐标单位为 **0.1mm**：

1. 换算 ROI 局部坐标：`roi_x = norm_x × 1600`，`roi_y = norm_y × 1600`。
2. 原有映射得到的局部机械坐标为 `(roi_y, roi_x)`；按当前标定规则将 X/Y 互换，
   得到 `(roi_x, roi_y)`。
3. ROI 中点 `(800, 800)` 对应实际机械坐标 `(600, 1400)`，因此执行平移：

```
机械X = roi_x - 800 + 600 = roi_x - 200
机械Y = roi_y - 800 + 1400 = roi_y + 600
```

局部坐标先四舍五入到整数（0.1mm单位）。
例如，旧映射得到 ROI 坐标 `(1126, 510)`，先互换为 `(510, 1126)`，
再以 ROI 中点为基准平移，最终发送 `(310, 1726)`。

### 7.2 量程

- ROI 边界映射到机械 X=`-200..1400`、Y=`600..2200`（即对应各轴的 0.1mm 坐标）
- 超出 ROI 的目标已被视觉端过滤，不会上报
- ROI 归一化坐标在视觉端钳位到 [0,1]；平移后的机械坐标不再钳位到 `0..1600`

### 7.3 换算示例

机械坐标值 `475` = **47.5mm**。

## 11. MCU 侧必须知道的行为细节

### 11.1 扫描请求时机
SCAN_REQ 必须在**托盘完全到位、物料静止后**再发送。视觉端收到请求后会先等 300ms 再采样，但仍建议 MCU 在机械到位信号稳定后再发请求。

### 11.2 扫描结果只推一次
SCAN_RESULT 发送后视觉端不保存清单。若 MCU 接收失败（CRC 错误/丢帧），**只能重新发送 SCAN_REQ 触发新一轮扫描**。

### 11.3 这些物料不会出现在清单里
- 中心点位于 ROI 区域之外的目标
- 颜色识别失败的物料（HSV 占比不足）
- 多帧投票中不稳定的目标（3 帧中出现少于 2 次）

因此**上报数量可能少于实际摆放数量**，MCU 流程不要假设清单完整。

### 11.4 角度字段不可用
当前固定发送 0xFFFF（ANGLE_NONE，无方向）。注意 0~359 是有效角度值，不要把 0xFFFF 当角度用；抓取姿态需 MCU 自行处理。

### 11.5 SEQ 的使用
SCAN_RESULT / ACK 的 SEQ **回用对应请求帧的 SEQ**，MCU 可用 SEQ 匹配请求与响应，过滤迟到帧。

### 11.6 复核流程说明
RECHECK_REQ 触发的是一次**全新的完整扫描**（含稳定等待+多帧投票），而非查询缓存结果，因此耗时与 SCAN_REQ 相同。复核比对只看形状+颜色，不看坐标；若需判断"物料是否被放错位置"，MCU 需自行比对 RECHECK_RESULT 中的坐标。

## 12. 参考代码（C 语言）

### 12.1 CRC8

```c
uint8_t crc8(const uint8_t *data, uint16_t len)
{
    uint8_t crc = 0;
    for (uint16_t i = 0; i < len; i++) {
        crc ^= data[i];
        for (uint8_t j = 0; j < 8; j++) {
            if (crc & 0x80)
                crc = (crc << 1) ^ 0x07;
            else
                crc = crc << 1;
        }
    }
    return crc;
}
```

### 12.2 帧构建

```c
// 返回帧长度，frame 缓冲区至少 134 字节
uint16_t build_frame(uint8_t cmd, uint8_t seq,
                     const uint8_t *payload, uint8_t len,
                     uint8_t *frame)
{
    frame[0] = 0xAA;
    frame[1] = 0x55;
    frame[2] = len;
    frame[3] = cmd;
    frame[4] = seq;
    for (uint8_t i = 0; i < len; i++)
        frame[5 + i] = payload[i];
    frame[5 + len] = crc8(frame, 5 + len);
    return 6 + len;
}
```

### 12.3 物料结构解析（小端）

```c
typedef struct {
    uint8_t  shape;

    uint8_t  rsv;

```

## 13. 测试用例

以下 HEX 帧均已在真实设备验证（CRC 已校验正确），可用串口助手直接发送测试：

### 13.1 完整流程

```
1) SYS_START:
   发: AA 55 02 42 01 01 02 1E
   收: AA 55 02 C2 01 00 02 xx      (0x00=成功, 0x02=版本号)

2) SCAN_REQ:
   发: AA 55 02 43 02 01 00 BB
   收: SCAN_RESULT (0x02)，约 1s 后到达，可能多帧分批

3) PICK_REPORT (序号1/圆形/蓝色/成功/累计3):
   发: AA 55 06 44 07 01 01 05 00 03 00 31
   收: ACK 0xC4，约 500ms 后到达

4) PING (特征码 DE AD BE EF):
   发: AA 55 04 4F 10 DE AD BE EF D5
   收: AA 55 05 CF 10 00 DE AD BE EF xx   (原样回显)

5) RECHECK_REQ (期望2件: 圆形蓝色 + 方形黄色):
   发: AA 55 05 45 03 02 01 05 02 03 C9
   收: RECHECK_RESULT (0x03)，约 1s 后到达
       示例: AA 55 0C 03 03 01 01 01 05 01 00 DB 01 B1 01 00 00 FA
       (match=1, 1件: 圆形蓝色 X=47.5mm Y=43.3mm)

6) DUMP_REPORT:
   发: AA 55 00 47 04 B0
   收: AA 55 01 C7 04 00 04             (立即应答)

7) FINISH (成功5/总数6/用时120s):
   发: AA 55 05 48 05 05 00 06 78 00 D4
   收: AA 55 01 C8 05 00 56             (立即应答)
```

### 13.2 SCAN_RESULT 示例解析

假设收到 PAYLOAD（24 字节）：

```
01 02 00 02 | 01 05 01 00 DB 01 B1 01 00 00 | 02 03 01 00 20 03 40 02 00 00
└头4字节───┘ └───────物料1 (10B)─────────┘ └───────物料2 (10B)─────────┘
```

- reason=0x01, total=2, batch=0, count=2
- 物料1：圆形(0x01) 蓝色(0x05) 可抓，X=0x01DB=475 → 47.5mm，Y=0x01B1=433 → 43.3mm
- 物料2：方形(0x02) 黄色(0x03) 可抓，X=0x0320=800 → 80.0mm，Y=0x0240=576 → 57.6mm

## 14. 故障排查

| 现象 | 可能原因 | 处理 |
|------|---------|------|
| 收不到任何响应 | 接线/波特率错误；帧格式错误 | 先发 PING 验证链路 |
| 0xC2 返回 0x02 | 协议版本号不是 0x02 | 修正 SYS_START 字节[1] |
| SCAN_RESULT 迟迟不到 | 首次扫描 NPU 未预热（旧固件）/ 扫描耗时 ~1s | 升级固件；超时设 ≥3s |
| 物料数量比实际少 | ROI 外 / 颜色未识别 / 多帧投票过滤 | 正常现象，见 11.3 |
| CRC 错误 | 波特率漂移、线材干扰、LEN 计算错误 | 检查 LEN 只算 PAYLOAD 长度 |
| 心跳 DISC | 1.5s 未发 HB_M | 确认 MCU 心跳周期 ≤1s |
| 复核 match 恒为 0 | 颜色未识别物料不参与比对 / 数量不符 | 看视觉端 [RECHECK] 日志的期望与实际清单 |
