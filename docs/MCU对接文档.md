# MCU ↔ MaixCAM2 对接说明（v3.1 周期快照）

接口规格以 [vision-link-protocol.md](vision-link-protocol.md) 为准。
应用版本为3.1.0，线上SYS_START/ACK协议版本字节仍为 **0x02**。
旧版请求扫描说明保存在 [archive/MCU对接文档-v3.0.md](archive/MCU对接文档-v3.0.md)。

## 帧格式与消息

115200 / 8N1，全双工，无流控。帧为 AA 55 LEN CMD SEQ PAYLOAD CRC8。
LEN≤128，CRC8覆盖帧头至载荷末尾，多项式0x07、初值0。
坐标和其它多字节整数为小端。

| CMD | 当前行为 |
|---|---|
| 0x01 | 视觉每250ms发送心跳 |
| 0x02 | 视觉每2000ms主动发送完整托盘快照 |
| 0x41 | MCU心跳更新LINK/DISC，视觉超时1500ms |
| 0x42 / 0xC2 | SYS_START，版本成功应答[0, 0x02] |
| 0x43 | 废弃，一律忽略，不扫描、不应答 |
| 0x44 / 0xC4 | PICK_REPORT，显示完成后回成功ACK |
| 0x45 / 0x03 | 保留复核，回应请求SEQ |
| 0x47 / 0xC7 | 保留旧倾倒兼容入口；新MCU不发送 |
| 0x48 / 0xC8 | 完赛，立即ACK，显示总结 |
| 0x82 / 0x83 | 不参与快照或复核结果重发 |
| 0x4F / 0xCF | 尚未统一，保持原实现：结果码+回显，最长回显127字节 |

## 快照

PAYLOAD = [snap_seq, total, batch=0, count] + count×piece。
total=count，0≤count≤12，LEN=4+10×count。超过12件只发送前12件，记录截断统计。
piece 为 [shape, color, pickable, 0, x:i16, y:i16, angle:u16]，angle恒为0xFFFF。

- 相机/模型初始化前，通信进程立即发送snap_seq=0、count=0的启动缓存；表示尚无已完成识别结果。
- 每次完成识别，快照号uint8加一。成功识别为空盘同样更新快照号并发空快照。
- 每2秒发送当前缓存；识别超时或异常时保持旧快照号和内容。
- 每次发送的帧SEQ自动递增，与视觉心跳共用计数器；重发旧缓存也分配新的帧SEQ。
- 快照不等待SYS_START、MCU心跳或0x82。FINISH后继续发送，用于验证链路。
- 复核结果不覆盖周期快照缓存；屏幕SCAN键只请求立刻刷新一次。
- shape 视觉端目前发 1–6 与 7–9（0x07 三棱柱、0x08 五棱柱、0x09 圆柱，`model_9974` 起启用）；`0x06` 异形仅作为未知 label 的兜底，仍不可抓。**MCU 需同步扩展 shape 解码表**。未知颜色不伪造颜色ID，过滤并记录统计。
- 业务按坐标域0≤x≤1800、0≤y≤2500过滤，不钳位。原规格三件样例包含负坐标，
  编码器保留黄金向量兼容性，但真实检测不发布该越界件。

## 调度与显示

link_service.py是独立解释器进程，只持有UART，不导入Maix媒体库。
媒体主进程通过非阻塞IPC发布完整识别结果、接收控制事件和提交显示完成信号。
单次采集、推理、配置重载或显示阻塞时，串口侧仍能发送心跳和旧快照。
通信进程以10ms轮询目标服务链路；实际首字节间隔仍需设备串口采样验收≤2500ms。
串口写返回值仍检查负值/截断并计数，进程退出会在媒体侧显式报错。

PICK_REPORT四要素：序号、形状/颜色名称、形状图示、累计成功数（同时显示本件成败）。
图示按形状ID绘制，不从重排的快照中猜测实物图片。
显示500ms完成后发送0xC4；显示失败、队列满、退出中断均不回假成功ACK。
同一报告重试只排队一次，已显示报告可再次ACK。失败可在下一次MCU重试时重新显示。
FINISH和复核格式保持原接口，PING不按未定稿的另一种格式迁移。

## 离线与联调验收

运行python tools/run_tests.py。覆盖黄金向量、空盘、12件、超12件、坐标域、
SEQ/快照号回绕、废弃0x43、复核隔离、显示后ACK、噪声恢复和慢媒体进程期间发送。

实机抓取至少10秒原始串口字节：
1. 0x02每帧LEN=4+10×count、batch=0、total=count。
2. 相邻0x02首字节间隔≤2500ms，慢识别时旧snap_seq和内容不变。
3. 不发0x43也有快照；发0x43不触发额外识别或应答。
4. 0x42应答版本0x02；四要素显示完成后才出现0xC4。
5. 复核和完赛保持接口，完赛后快照继续发送。

独立通信不能修复整机掉电、内核失去调度或ISP硬件故障；
这些仍需结合AXERA日志、故障线程栈和供电测量排查。
