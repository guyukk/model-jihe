## 1. 项目速览

视觉端跑在 MaixCAM2，负责识别载物盘里的几何体（形状 + 颜色 + 位置 + 角度），每 2 秒把整盘快照通过 UART4 主动推给 STM32 侧的 MCU；MCU 拿到快照后驱动机械臂或吸盘做抓取，再回写抓取报告，视觉端刷新显示并 ACK。工程里包含两个独立 App：

- **`test1`（几何体检测）**——正式参赛程序，位于仓库根目录。
- **`labcal`（颜色标定）**——现场使用的辅助 App，位于 `calibration/lab_app/`，独立打包、独立在设备桌面上启动，不占串口。

两个 App 共享 `shared/lab_color.py` 这一份 LAB 判色算法（单一来源，两边同时受益）。

媒体主进程 `main.py` 与通信进程 `link_service.py` 分家：`main.py` 负责相机、NPU、显示、触摸；`link_service.py` 是**独立解释器进程**，独占 `/dev/ttyS4`，通过 socketpair IPC 从媒体侧接收最新识别结果、向媒体侧回送控制事件。这样即使相机或推理卡住，心跳与旧快照仍能量保持续推给 MCU。

## 4. 视觉 ↔ MCU 串口协议（v3.1）

> 权威源：`docs/vision-link-protocol.md`（ReadOnly 属性，改前先 `attrib -R`）与 `docs/MCU对接文档.md`。这里只列 MCU 方最常查阅的要点。

### 4.1 物理层与帧格式

- UART4 `/dev/ttyS4`，**115200 / 8N1**，全双工，无流控。
- 帧：`AA 55 | LEN | CMD | SEQ | PAYLOAD | CRC8`
  - `LEN` = PAYLOAD 字节数，最大 128。
  - `SEQ` 从 0 递增，回绕 0xFF→0x00，心跳与快照共用同一计数器（重发旧快照会分配新 SEQ）。
  - `CRC8` 多项式 `0x07`、初值 `0x00`、**覆盖 `AA 55 LEN CMD SEQ PAYLOAD`**（除 CRC 自身与帧头之外全部字段）。
  - 所有多字节整数（坐标、SEQ 之外的 u16 等）**小端**。

### 4.2 CMD 表

| CMD | 方向 | 语义 | 备注 |
|---|---|---|---|
| 0x01 | 视 → 端 | 心跳 payload=`[state, err, 0x00]` | 每 250 ms 一帧 |
| 0x02 | 视 → 端 | 托盘快照 | 每 2000 ms 一帧；空盘也发；识别慢时可带同一 snap_seq 重发缓存 |
| 0x03 | 视 → 端 | 复核结果 | 由 0x45 触发 |
| 0x04 | 视 → 端 | 告警 payload=`[code]` | 目前未主动使用 |
| 0x41 | 端 → 视 | MCU 心跳，刷新 LINK/DISC | 视觉端 1500 ms 内无 0x41 判为掉线 |
| 0x42 / 0xC2 | 端 → 视 / 视 ACK | SYS_START，成功回 `[0, 0x02]` | 版本握手 |
| 0x43 | — | 已废弃 SCAN_REQ | 视觉收到直接忽略、不应答；不再依赖请求触发 |
| 0x44 / 0xC4 | 端 → 视 / 视 ACK | PICK_REPORT（抓取完成上报） | 显示完成后才回 ACK |
| 0x45 / 0x03 | 端 → 视 / 视回 | 复核请求 | 保留 |
| 0x47 / 0xC7 | 端 → 视 / 视 ACK | 旧倾倒上报入口，兼容保留 | 新 MCU 不发送 |
| 0x48 / 0xC8 | 端 → 视 / 视 ACK | FINISH 完赛 | 立即 ACK，视觉显示总结 |
| 0x82 / 0x83 | 视 → 端 | 快照 / 复核结果的"旧请求 ACK" | **不参与新流程，也不触发快照重发** |
| 0x4F / 0xCF | 端 → 视 / 视 ACK | PING 链路测试 | 结果码 + 回显（≤127 B） |

### 4.3 心跳 payload（0x01）

3 字节：`[state u8, err u8, 0x00 u8]`

`state` 取值（`protocol.py` STATE_*）：`0 INIT, 1 READY, 2 SCANNING, 3 PICKING, 4 DISPLAYING, 5 RECHECKING, 6 DUMPING, 7 FINISHED, 8 FAULT`。正常待机为 1，扫描中为 2。

### 4.4 快照 payload（0x02）

```
[snap_seq u8, total u8, batch=0x00 u8, count u8] + count × 10B piece
LEN = 4 + 10 × count       0 ≤ count ≤ 12
```

- `snap_seq`：视觉本地从 0 递增的快照号（回绕 0xFF→0x00）；重发缓存时 `snap_seq` 不变、`SEQ` 变。
- `total`：与 `count` 相同（保留字段，兼容多批扩展）。
- `count=0` 也发（空盘心跳）。超过 12 件只发前 12 件，剩余记入 `filter_stats.truncated`。

### 4.5 每件 10 字节

`struct.pack('<BBBBhhH', shape, color, pickable, 0, x, y, angle)`

| 偏移 | 字段 | 类型 | 语义 |
|---|---|---|---|
| 0 | shape | u8 | 见 4.6 形状码表 |
| 1 | color | u8 | 见 4.7 颜色码表 |
| 2 | pickable | u8 | 1=可抓；0=留在盘里（只进复核期望清单） |
| 3 | rsv | u8 | 恒 0 |
| 4–5 | x | **i16 LE** | 机械 X，单位 0.1 mm |
| 6–7 | y | **i16 LE** | 机械 Y，单位 0.1 mm |
| 8–9 | angle | u16 LE | 目标朝向角，`0xFFFF` 表示未计算/不可用 |

坐标有效域：`x ∈ [0, 1800]`, `y ∈ [0, 2500]`（0.1 mm）。越界的件在视觉端被过滤丢弃、不进快照，会记入 `filter_stats.invalid_coord`。**视觉端不钳位、只丢弃**，MCU 应认为收到的坐标都在此范围内。

`angle` 是形状主轴方向（圆锥/棱台为 0xFFFF，立方/棱柱类才会算）。MCU 消费时**必须先判 `angle != 0xFFFF`**，不能把 65535 当成真角度。

### 4.6 形状码表（**MCU 侧本轮需同步**）

| 字节 | 名称 | 模型 label | pickable | 备注 |
|---|---|---|---|---|
| 0x01 | 圆锥 | `cone` | 是 | |
| 0x02 | 立方体 | `cube` | 是 | |
| 0x03 | 棱锥 | `pyramid` | 是 | 任意棱锥（三/四/…棱锥）都归此类 |
| 0x04 | 长方体 | — | 保留 | 视觉目前不发，为未来 label 追加预留 |
| 0x05 | 六棱柱 | `6edge` | 是 | 沿用 v3.0 语义 |
| 0x06 | 异形 | — | **否** | **未知 label 兜底**：`SHAPE_MAPPING.get(shape, 6)`；MCU 应视为不可抓 |
| 0x07 | 三棱柱 | `3edge` | 是 | **新**，MCU 需加解码表 |
| 0x08 | 五棱柱 | `5edge` | 是 | **新**，MCU 需加解码表 |
| 0x09 | 圆柱 | `0edge` | 是 | **新**（`0edge` 是 label 命名，视觉/显示都按"圆柱"处理） |

MCU 端若维持旧的 1–6 码表，收到 0x07/0x08/0x09 会按未知丢弃；这不影响其它件，但三/五棱柱与圆柱就漏抓了。

### 4.7 颜色码表（未变）

`0x01 红 / 0x02 橙 / 0x03 黄 / 0x04 绿 / 0x05 蓝 / 0x06 紫 / 0x07 黑 / 0x08 白`。未知颜色在视觉端被过滤，不发进快照，`filter_stats.unknown_color` 计数。

### 4.8 时序

- 心跳：视觉 250 ms 一帧。
- 快照：视觉 2000 ms 一帧，**独立于 SYS_START / MCU 心跳 / 0x82**；FINISH 之后仍继续发，用于链路的持续验证。
- MCU 心跳：建议 ≤ 500 ms；视觉 `LINK_TIMEOUT = 1.5 s`（收到 0x41 才算活着）。
- MCU 端超时判视觉掉线：建议 2500 ms（约 1.25 倍快照周期）。
- 屏幕 SCAN 键：只请求"立刻刷新一次"，不影响周期。

### 4.9 坐标映射

视觉端从像素 → 机械坐标走线性映射：`config.py` 中

```
COORD_SCALE_FACTOR = 1600       # ROI 两轴各 160 mm
COORD_ROI_CENTER = 800          # ROI 局部坐标中点
COORD_MECHANICAL_CENTER_X = 600 # 该中点在机械坐标系里的标定值
COORD_MECHANICAL_CENTER_Y = 1400
```

即 `mech_x_mm = 160 * (px_in_roi - 800) / 1600 + MECH_CX_MM`，y 同理。装机/换相机后这几个常量必须重标。

## 5. 模型现状（**比赛前必须处理**）

`model_9974.mud` 声明 7 类 label：`cone / cube / pyramid / 5edge / 6edge / 3edge / 0edge`。**实际训练数据只覆盖 cube / pyramid / cone 三类，其余 4 类（5edge、6edge、3edge、0edge）当前不可靠**：可能不出框、也可能把别的物体错标成这些 label。

短期缓解：`config.py::SHAPE_MAPPING` 里保留 4 条未训练类，只是为了让 `test_shape_mapping.py` 的"mapping.keys() == .mud.labels"守护成立；一旦识别到就照常发字节。真正的修复路径有两条：

1. **补训练 5edge / 6edge / 3edge / 0edge 的样本**（推荐），产出新的 `.mud` 三件套放 `models/`，改 `config.py::_resolve_model_path()` 里的 `mud_name` 与 `app.yaml::files` 里的模型三行即可。`tools/package_app.py` 从 `app.yaml` 派生模型文件名，未来换模型不再需要动 packager。
2. **临时降级**：如果比赛前来不及补训练，可以在 `vision.py` 结果过滤处把 4 个未训练类丢弃，或让 `SHAPE_MAPPING` 只保留 3 类。但这样 `test_shape_mapping.py` 会 FAIL，需要同时缩 `.mud` 或改测试期望。**不建议**——现场调试期保留 7 类映射有助于快速看到误检分布。

`.mud` 里 label 顺序 = 模型输出通道顺序，改类别请同步改 `.mud` 而不是改 `SHAPE_MAPPING` 的顺序。

## 6. 颜色识别现状

`COLOR_MODE = "auto"` 时：

- 设备上存在 `/root/lab_colors.json` 且 `version=1` schema 有效 → 走 **LAB 多样本近邻判色**（每类至少 4 个实物样本，不合并成大阈值；距离超样本半径或前两类距离差 < 8 时打"颜色估测"标记但仍发颜色字节）。
- 文件缺失或损坏 → 回退 **HSV** 四色（红/黄/蓝/白），其它色一律判为未知颜色被过滤。

**比赛现场必须重跑一次颜色标定**，原因：光源环境（色温、强度、方向、阴影）会变，同一批物料在实验室和赛场可能差一档 L 值。

标定 App 用法见 `docs/LAB颜色标定说明.md`；关键点是每类 ≥ 4 次点击取样，样本要覆盖不同摆放位置与轻微遮挡。目前手上没有紫色实物，紫色那栏可以保持未启用。

### 7.3 远程观察

- `python .maixpy/remote.py "tail -80 /root/startup.log"` —— 结构化启动阶段事件（BOOT_APPLICATION → maix_import → uart_guard → uart_worker → model → camera → display → font_touch → warmup → READY）。**卡在哪个 phase 就是那个 phase 抛异常**。FAILED 事件的 `stack` 字段直接是 Python traceback。
- `/root/diag.log` —— 媒体循环 SCAN_TIMING / MEDIA / SNAP_SCAN / SNAP_DONE / MEDIA_EVENT。

- `/root/fault_dump.txt` —— 崩溃行摘要（boot/run/mono/pid 四元组）。
- 想手动跑一次 main.py 看 stdout：必须**先停 launcher**，否则 `display.Display()` 会 `RuntimeError: VO init failed`（0x80038a80）。参考 `.maixpy/deploy_test1.py` 里 SCRIPT 段的 kill/restore 模板。

## 8. 已知坑与硬约束

1. **`app.yaml::files` 是打包的唯一真相**。少写 `lab_color.py` → 设备 `import lab_color` 崩在 `maix_import OK` 之后；少写 `model_9974.*` → `nn.YOLO26` 加载报文件不存在。2026-10-13 曾因此炸过一次（本机 `app.yaml` 有未提交的删除）。修复方式：`git restore app.yaml` 再重打包。
2. **`shared/lab_color.py` 挪动或改名**要同步 4 处：`tools/package_app.py::locate()`、`tools/package_lab_app.py` 源路径、`tests/_stubs.py::ensure_project_path()` 挂载 `shared/` 到 `sys.path`、`tests/test_packaging.py::locate()`。
3. **`vision-link-protocol.md` 是 Windows ReadOnly 属性**，改前先 `attrib -R`，改完 `attrib +R` 还原。PowerShell 里嵌 `$f=...` 会被本环境的 bash 变量展开吞掉，用 `attrib` 命令。
4. **VO/display 需要 launcher 交接**：SSH 里 `python3 main.py` 会 `VO init failed`，属正常，不是 bug。要么从设备桌面点，要么按 `.maixpy/deploy_test1.py` 那样先 `pkill launcher_daemon` 再跑。
5. **Bash 工具实际由 `/usr/bin/bash` 执行**（即便 runtime 标 `cmd.exe`），不要用 `cd /d`，Windows 路径用正斜杠或转义，工作目录用 `dir_path` 参数。
6. `angle=0xFFFF` 是"未计算"，不是 360°。MCU 消费前必须判 sentinel。
7. `pickable=0` 的件仍会进快照 payload（占 10B），MCU 要按位跳过，不能靠"件数少"判断。
8. `0x43 SCAN_REQ` 已废弃，收到直接忽略、不应答，MCU 若还发这个字节视觉不会有任何反应。
9. `0x82/0x83` 不参与快照或复核结果的重发；ACK 只是链路验证。
10. `.maixpy/` 目录里几十个 `.py` 脚本，本轮清理只归档了 `cmds/logs`，业务脚本仍在原地（哪些活跃无法自动判定，避免误删）；`mcu_sim/` 与 `config.json`/`device_credentials.local.json`/`uart_code_audit/` 保留。

## 9. 后续工作（按优先级）

### 9.1 【装机后立即做】载物盘 ROI 范围标定

装机后相机与托盘的相对位置固定，但每次装配都会有几毫米级偏差，必须重标 ROI 与机械中心。

- **像素 ROI**（视觉端裁掉背景）：改 `config.py::ROI_X/Y/WIDTH/HEIGHT`，或者直接写 `/root/roi_config.json` 让程序覆盖。参考 `docs/ROI使用说明.md` 与 `calibration/calibrate_roi_serial.py`。基准分辨率是 320×256；模型输入 640×640 会自动缩放。
- **机械映射**：改 `config.py::COORD_MECHANICAL_CENTER_X/Y` 与 `COORD_SCALE_FACTOR`。做法：把某已知物体摆到机械坐标系下的两个参考点，读视觉发出来的 x/y，反算 scale 与 offset。
- **验收**：`tools/mcu_sim.py` 侧看 `SNAPSHOT_COORD_X_MIN/MAX` 与 `Y_MIN/MAX` 覆盖到实际物料范围，`filter_stats.invalid_coord` 应为 0。

### 9.2 【比赛现场调试前必做】颜色标定

现场光照与实验室不同，LAB 判色必须重跑：

1. 从设备桌面点"颜色标定"（`labcal` App），或 `python .maixpy/push_zip.py dist/maix-labcal-v1.0.0.zip` 先推一次。
2. 按 8 色（红橙黄绿蓝紫黑白）逐色点击取样，**每类 ≥ 4 个样本**（紫可留空，因无实物）。样本要覆盖盘内不同位置与轻微阴影。
3. 保存到 `/root/lab_colors.json`。
4. 退出标定 App，从桌面点"几何体检测"启动正式程序；主页顶部应显示 `LAB N/8`。
5. `python .maixpy/remote.py "cat /root/lab_colors.json"` 验证文件真的落盘、`version=1`、各类 `samples ≥ 4`。
6. 空跑几次扫描，`/root/diag.log` 里看 `color_ms`、`filter_stats.unknown_color` 是否合理。

参考文档：`docs/LAB颜色标定说明.md`、`docs/HSV标定说明.md`（回退路径）。

### 9.3 【核心模型工作】继续训练 5edge / 6edge / 3edge / 0edge

当前 `model_9974` 只有 `cube / pyramid / cone` 三类可靠；其余四类需要补充训练数据。步骤：

- 采集实物照片（每类 ≥ 200 张，多角度、多光照、有遮挡样本）。
- 用与 9974 相同的 YOLO26 训练管线导出 `.mud + _npu.axmodel + _vnpu.axmodel` 三件套。
- 命名建议 `model_<新编号>.*`，放进 `models/`。
- 改 `app.yaml::files` 三行模型条目 + 改 `config.py::_resolve_model_path()` 里的 `mud_name` 与 fallback 字符串。
- 若新增或删减 label 种类，同步 `config.py::SHAPE_MAPPING` 与 `protocol.SHAPE_*` 常量 + `screen_ui.SHAPES_ZH/EN` + `main._draw_piece_picture`。跑 `python tools/run_tests.py`，`test_shape_mapping.py` 会自动指出漂移。
- 若引入了 0x07/0x08/0x09 之外的新形状字节，MCU 端要**同步扩表**。

### 9.4 【MCU 方】形状码表扩展

- 增加 `0x07 三棱柱 / 0x08 五棱柱 / 0x09 圆柱` 三个 case；抓取动作按现有可抓形状一致处理。
- 保留 `0x06` 作为"未知异形"不可抓兜底。
- `0x04` 保留，暂不使用。
- `angle` 消费前判 `0xFFFF` sentinel。
- 收到 `pickable=0` 的件不驱动机构，但仍计入快照数量。

### 9.5 【可选加固】

- 现在 `test_packaging.py` 只保证"声明的都能定位到"，不保证"该有的都声明了"（比如 `lab_color.py` 被误删就漏检）。可以加一条测试扫描 `vision.py` 里的 `^import (\w+)$` 与项目内文件同名者必须出现在 `app.yaml::files`。
- `.maixpy/deploy_safe.py` 只推部分 .py 文件；`push_zip.py` 补齐了整包推送。可以考虑把 `deploy_safe.py` 改成基于 `push_zip.py` 的薄壳。
- `packaging` 与 `shape_mapping` 两个测试里都有对 `mud_name is None` 的处理，一个用 `check(..., mud is not None)`，一个直接 `join(..., None)` 会 TypeError。可以统一提前 bail。
