# 正式使用界面与诊断

从设备桌面启动应用，等待首次识别。主页保留最新完整识别所采样的画面，
相机仍按原流程采集，五帧投票、50ms帧间等待和2秒快照不变。
界面覆盖层画到副本，不会成为下一轮颜色采样的数据。
多帧结果为投票合并值，背景为本轮最后一张实际采样帧；运动物料的平均坐标
仍可能滞后，静止托盘与真实抓取过程需分别验证。

“物料详情”打开周期识别清单，坐标单位为毫米，显示可抓标志。
未上报物料按颜色未知、坐标越界或超过12件标注；不钳位坐标。
每页4件（每件2行），自动刷新保留页号，页数变少时才调整。
返回、上页、下页均在详情页底部。长按退出视觉程序1.5秒；拖出按钮则取消。
等待及采样边界会处理触摸，单次相机、推理或显示调用阻塞时无法立即响应。

主页状态含义：

| 状态 | 含义 |
|---|---|
| MCU心跳有/无 | 最近是否收到MCU心跳，不能据此确认双向通信正常 |
| 结果年龄 | 最近完整周期识别完成后经过的单调时间 |
| 结果滞留 | 超过15秒没有完整周期识别；重发旧快照不会刷新年龄 |
| 本轮待发送 | 本轮结果尚无通信进程完整写出确认 |
| 本轮已写出UART | 通信进程的实际write完成，不能据此确认MCU收到 |
| 识别失败，保留旧结果 | 本轮失败，旧画面/清单/完成时间保留 |
| 首次识别前 / 未检出 / 全部过滤 | 分别表示尚无结果、有效空盘、检出但没有可上报件 |

框和名称颜色跟随本轮写出状态：待发送为黄色、完整写出为绿色、被过滤为红色。
详情里的历史累计识别/写入/截断/IPC/日志错误与当前告警分开，恢复后当前告警清除，累计计数保留。
复核结果有独立缓存，不覆盖主页和详情。完赛摘要保持到下一次有效SYS_START或退出；
后台识别和快照继续。启动由MCU控制，主页不提供启动、暂停、重启、手动扫描或配置重载。

PICK_REPORT显示序号、名称、形状图示、累计成功数，另显示本件成功/失败。
圆锥使用椭圆底面，棱锥使用棱线。显示持续完成后才发送0xC4；
期间普通页面操作延后，退出或显示异常不回成功应答。持续时间仍为原配置。

中文使用设备已有`/maixapp/share/font/SourceHanSansCN-Regular.otf`，
按照[官方字体说明](https://wiki.sipeed.com/maixpy/doc/zh/vision/image_ops.html)加载并选为默认字体。
加载失败时按钮、主页、详情、分拣和完赛文案均改为英文。

## 取证与日志

Maix导入前启用故障栈和启动记录。`/root/startup.log`记录Maix、UART守护句柄、
独立通信进程、模型、相机、显示、字体触摸、预热的ENTER/OK/FAILED及故障栈。
每条记录包含系统boot ID、应用run ID、PID、单调时间和墙上时间。
启动关键记录flush+fsync，提高断电前保存的机会，无法保证底层存储或供电故障时绝对完整。

`/root/diag.log`记录媒体循环、RSS、识别失败、结果版本、年龄、过滤数，
各帧采集+副本耗时、模型推理耗时及检测总耗时，媒体侧协议服务最大间隔。
`/root/link.log`由通信进程独立写入，包含完整/截断/失败发送、IPC丢事件、
缓存版本/年龄/重发、UART服务最大间隔。媒体线程冻结时，此日志可揭示通信仍在发旧结果。
心跳正常不能证明媒体线程正常。

普通日志每份2MiB，保留3份轮转历史。通信日志通过256条有界队列异步落盘，
积压丢失和磁盘错误有累计计数；不能将有缺口的记录当作完整证据。
`fault_dump.txt`在启动时轮转，运行中保持文件描述符有效，向主进程发SIGUSR1可抓栈。
本阶段未增加任何自动重启机制，也未更改UART4或ISP设置。

## 验收与仍待验证事项

离线覆盖首次启动、空盘、正常件、全部过滤、旧结果保留、分页、干净采样副本、
时钟跳变、长按取消、等待退出、字体失败、PICK成功显示门控、模型/相机初始化失败和日志故障。
PC布局预览使用设备字体及实际绘制代码，不能替代设备上的视觉检查。

现场需要非空物料持续30分钟，核对界面、2秒快照/2500ms上限、PICK/复核应答，
并保存串口原始记录及设备boot/run证据。空盘测试不能验收识别率、中文物料名称、
实物分拣图示、机械坐标或电机共用电源下的稳定性。

以下问题单独处理：ROI左侧12.5%会生成负X而过滤；等待300ms不能保证物料已静止；
复核队列积压/重试和跨轮残留；初始化前UART4回环触发重启；现有安装包模型依赖。
当前仍不把历史画面冻结后的重启归因于MCU、供电或媒体框架中的任意一项。
