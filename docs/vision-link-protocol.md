# MCU ↔ 视觉 串口对接协议（周期快照版 · 对外）

版本：**v3.1-draft**（2026-10-12）　适用：MaixCAM2 视觉 ↔ STM32F407 电控
承接：视觉侧《MCU对接文档 v3.0》。本文件**只改动"识别结果怎么上来"这一层**，
其余帧格式、字段、时序窗、显示义务与 v3.0 一致。

★ 相对 v3.0 的唯一模型变化：**视觉每 2s 扫描一次托盘，主动推一帧整盘快照；
电控不再发 `0x43 SCAN_REQ` 请求扫描。** 心跳、失联判定窗、`0xC4` 锁步全部不变。

---

## 1. 物理层与帧格式（不变）

- 串口：115200 / 8N1，全双工，无流控。视觉 UART 与电控 USART2 对接。
- 帧：`AA 55 | LEN | CMD | SEQ | PAYLOAD(LEN 字节) | CRC8`，整帧长 = `LEN + 6`。
- `LEN` = 载荷字节数，上限 **128**（ ⇒ 整帧最长 134 字节）。
- `CRC8`：多项式 `0x07`、初值 `0x00`、不反射、不异或输出；**覆盖范围 = `AA` 起直到载荷末字节**（含 `AA 55 LEN CMD SEQ`）。
- 所有多字节整数一律**小端**。
- `SEQ`：发送方各自从 0 递增（uint8，溢出回绕）。视觉的 `0x02 / 0x01` 共用一个自增计数即可。

坏帧（CRC 错 / `LEN>128`）接收方**直接丢弃并重同步**，不回错误应答；可靠性靠"下一帧 2s 后就来了"，不靠重发。

| CMD | 名称 | 方向 | 状态 |
|---|---|---|---|

| `~~0x43~~` | ~~SCAN_REQ 扫描请求~~ | ~~MCU→视觉~~ | **★ 本版作废**：视觉收到 `0x43` 一律忽略、不应答 |

| `0xC8` | ACK FINISH | 视觉→MCU | 不变 |

## 3. `0x02` 托盘快照（本文件的核心）

### 3.1 载荷逐字节

| 偏移 | 字段 | 宽度 | 取值 |
|---|---|---|---|
| 0 | `snap_seq` | 1 | 快照号：每产生一次**新的**扫描结果就 +1（uint8 回绕）。同一快照因链路原因重复发送时**保持同号** |
| 1 | `total` | 1 | 本快照件数，**恒等于 `count`**（见 §3.3） |
| 2 | `batch` | 1 | **恒为 `0`**（本版不分批，保留字段只为与 v3.0 的字节布局兼容） |
| 3 | `count` | 1 | 本帧携带的件数 = `total`，≤12 |
| 4+ | `pieces` | 10×count | 每件 10 字节，见 §3.2 |

`LEN = 4 + 10 × count`；`count = 0` 时 `LEN = 4`（**空盘也必须发这一帧，不许静默**）。

> 兼容说明（给实现者）：偏移 0 在 v3.0 里叫 `reason`。改成快照号后，**当前电控固件不读这个字节**，
> 因此按本表发不会把现有链路打断；而 `batch=0 / total=count` 恰好满足现有累积器的判据
> （"一帧即一次完整快照"）。也就是说：**视觉可以先照本文件实现，我方改动可以后做。**

### 3.2 每件 10 字节（与 v3.0 完全一致，未改一个字节）

| 偏移 | 字段 | 类型 | 说明 |
|---|---|---|---|
| 0 | `shape` | u8 | `0x01` 圆锥 / `0x02` 立方 / `0x03` 棱锥（任意棱锥） / `0x04` 长方（预留） / `0x05` 六棱柱 / `0x06` 异形（未知 label 兜底，不可抓） / `0x07` 三棱柱 / `0x08` 五棱柱 / `0x09` 圆柱。`0x07`–`0x09` 自 `model_9974` 起启用，**MCU 需同步扩展识别码表，否则新形状会被当未知处理** |
| 1 | `color` | u8 | `0x01` 红 `0x02` 橙 `0x03` 黄 `0x04` 绿 `0x05` 蓝 `0x06` 紫 `0x07` 黑 `0x08` 白 |
| 2 | `pickable` | u8 | 1=可抓，0=不可抓（留在盘里，只进复核期望清单） |
| 3 | 保留 | u8 | 填 `0x00` |
| 4 | `x` | i16le | 单位 **0.1mm**，托盘取件坐标系 |
| 6 | `y` | i16le | 同上 |
| 8 | `angle` | u16le | 目前**恒填 `0xFFFF`**（视觉不提供朝向），我方按"无角度"处理 |

**坐标有效域（硬要求）**：`0 ≤ x ≤ 1800`、`0 ≤ y ≤ 2500`（即 0–180.0mm / 0–250.0mm）。
越界的件我方**不下发电机**，判为"这一件放弃"，仍会显示并上报 `PICK_REPORT(result=0x02 R_PARAM)`，
**不会**因此停机、也不会要求重扫。所以标定漂移的代价只是丢件，但请不要把越界坐标当正常值发。

### 3.3 快照语义（整盘，不是增量）

- 每帧是**当前托盘的完整快照**：盘里此刻识别到的每一件都出现在这一帧里，没出现就是"没看到"。
- `total == count`，**一批一帧发完**，不拆多帧。规则上限 12 件；若某次检出 >12 件，请只发 12 件并把 `total` 填成实际发送条数（我方按"快照=这 12 件"处理）。
- 我方收到快照后的行为（你们需要知道的语义）：
  - 快照**不打断正在执行的这一件**——机械臂已经在飞的件按它被选中时的坐标走完 抓→放→上报；新快照从**下一件**开始生效；
  - 快照里消失的件不再排进队列；新出现的件从下一件起可被选中；
  - **"同色同形进同一格"的映射表不随快照重排**（赛规：混装 = 该格 0 分），所以新快照不会改变已经投过件的格位；
  - 同一 `snap_seq` 再来一次 ⇒ 视为重发，我方回 `0x82` 但不重建队列。

### 3.4 发送时机（★ 硬约束）

1. **视觉进程起来就开始推**，不等我方任何请求；我方上电自检、按一键启动之前收到的快照会被记录但不启动业务（赛规：待机不许动机构）。
2. 周期 **2s**：两次发帧的**首个字节**间隔不得超过 **2500ms**——这是我方的失联判定窗（`PROTO_LINK_DOWN_MS`），本次**不改**。
   ★ 如果某轮识别耗时超过 2s，**也要在窗口内发一帧**：宁可重复上一帧的快照（`snap_seq` 保持不变、内容照旧），
   也不要让线路静默超过 2.5s。否则我方判失联 → 广播急停 → 视觉屏上报"通信中断"，实际只是我方没收到字节。
3. `count=0` 的空快照合法且必须发，含义是"此刻没识别到"。**我方不会**因为一帧空快照判定失败或提前完赛——本轮结束只能由 `0x48 FINISH` 决定。
4. 我方发完 `0x48 FINISH` 并收到 `0xC8` 之后进入完赛态，此后收到的快照我方不再消费；视觉可继续推（用于验证链路）也可以停止，两种都不影响判定。

## 4. 时序（新版主循环）

```text
视觉上电 ──每 2s──> 0x02 快照 ──> MCU 回 0x82（视觉可不接收）
                                   │
MCU 自检+回零 ──> 0x42 SYS_START ──> 视觉回 0xC2 [result, ver]     ← 版本字节必须是 0x02
                                   │
                        （按 PA0 一键启动，MCU 进入抓取循环）
                                   │
   每件：0x44 PICK_REPORT(序号/名称/图片/成功总数) ──视觉先显示──> 0xC4 ACK
                                   │                     ↑
                                   │        ★ 收到 0xC4 之前，MCU 绝不起动下一件（锁步）
                                   │
   队列跑完 ──> 0x45 RECHECK_REQ ──> 0x03 RECHECK_RESULT ──> 0x83
                                   │
                      相符/不符都只记一笔 ──> 0x48 FINISH ──> 0xC8
```

被删掉的一段：v3.0 里"MCU 发 `0x43` → 视觉扫描 → 分批回 `0x02` → Σcount==total 关事务 →
超时则 MCU 原 SEQ 重发 `0x43`"整条请求/响应链，以及 `4=QUEUE_EMPTY`（队列跑空确认重扫）、
`3=LINK_RECOVER`（断链恢复重扫）两个扫描原因。它们解决的问题（"数据什么时候是新的"）
现在由 2s 周期本身解决。

## 5. 超时、失联与可靠性

### 5.1 判定窗（**全部保持 v3.0 的数值**）

| 项 | 值 | 说明 |
|---|---|---|
| MCU 心跳周期 | 500ms | 不变 |
| 视觉心跳周期 | 250ms | 不变 |
| **快照周期** | **2000ms** | 本版新增 |
| MCU 判失联 | 连续 **2500ms** 无对侧心跳 **且** 无任何串口字节 | 不变；★ 所以 §3.4 第 2 条是硬要求 |
| 视觉判 DISC | 1500ms | 不变；只驱动屏上 LINK 文字，不参与协议逻辑 |
| SYS_START 重试 | 超时 1000ms、事务内重试 3 次（共 4 帧），耗尽后**永续重试**（实测约每 2s 再发一帧）直到收到 `0xC2` | 视觉若还没起进程，我方不会卡死，只是不停重发 |
| PICK_REPORT `0xC4` 等待 | 1500ms × 4 次尝试 | 不变；耗尽后我方**放行下一件并记 `DISPLAY_FAULT`**（宁丢一分不卡 15 秒） |
| 复核 | 2000ms × 3 | 不变 |
| 完赛 | 2000ms × 3 | 不变 |
| ★ 我方全局动作看门狗 | 开表后 **13s** 无任何机械动作 ⇒ 主动 `0x48` 收尾 | 2026-10-12 新增，串口打 `ACTWD`。取 13s 是因为它必须大于一次合法扫描事务的最坏时长 |

### 5.2 阻塞期（视觉要知道我方在做什么）

我方抓取段有 **约 1s** 的串行阻塞（Z 下降→合爪→抬起，每段舵机驻留 350ms），期间不分发串口帧、
但**心跳照发**（阻塞封装里每 1ms 泵一次）。所以视觉看到"MCU 静默约 1s"是正常现象，不是死了。
反过来的那条硬约束是：视觉扫描/屏显期间如果整条线程阻塞、连串口都不读，就会让我方心跳堆积
——这也是判定窗留 2500ms 而不是 1500ms 的原因。

### 5.3 为什么 `0x82` 不再是可靠性机制

v3.0 规定视觉不实现 `0x82` 的接收、也不因缺它重发批。**本版把这个"缺陷"变成了设计**：
快照是幂等的整盘数据，任何一帧丢在途，代价只是"我方手里的数据旧了 2s"，下一帧自动修正。
因此：

- 视觉**不需要**为快照做重发、超时、序号回绕处理；
- 我方仍会回 `0x82`，用途只剩"链路上我看到你了"的自证；
- 但如果连续两帧快照都没收到，我方会判失联（§5.1），所以别把发帧挂在可能被 GC/IO 卡住的线程上。

## 6. 显示义务与赛规对应（不变，列出来对齐口径）

- 每抓一件**必须先在屏上显示四要素**（序号 / 名称 / 图片 / 成功总数），显示完成后视觉才回 `0xC4`；
  我方**收到 `0xC4` 之前绝不起动下一次抓取**。赛规按行给分，这条是得分前提。
- 赛规"15 秒无动作或无信息显示 = 本轮结束"：显示由视觉屏负责常显（心跳/状态行），
  我方另有 T1 副显屏但不参与门控。
- 一键启动 = 电控核心板 PA0 按键；**运行中不得触摸机构或使用遥控**。视觉屏上的"开始"按钮不能替代它。

## 8. 未定稿（**别按任何一种实现**）

1. **PING 应答格式**（`0x4F → 0xCF`）现在三处口径互相矛盾：正文写"带结果码 + 原样回显"、
   我方黄金向量是**不带结果码**的 `aa 55 04 cf 10 de ad be ef 39`、视觉仿真实现成 `LEN=5`。
   本文件**有意不写这条**，等电控与视觉单独定一次再补 §2 的样例。
2. **复核 `0x45/0x03/0x83`** 是否保留：有了每 2s 的整盘快照，"确认盘里只剩不可抓件"这件事
   可以只看下一个快照得到，不必再发一次专门的复核。倾向保留到联调通过再议，本轮**不改**。
3. **`angle` 字段** 目前恒 `0xFFFF`。若视觉将来提供夹取朝向，需要单独定稿（我方机构今天不用它）。

## 9. 联调首日三步（每步都能机判）

1. **不接视觉，只量心跳**：MCU 上电按 PA0 前先确认串口有 `AA 55 03 41 …` 每 500ms 一条
   （`tools/can_monitor.py` 或串口助手）。→ 证明我方出帧与波特率。
2. **视觉只推快照**：接上视觉，不看别的，抓 10s 原始字节，判据三条——
   ① 每 2s 一条 `0x02`，`LEN = 4 + 10×count`；② `batch` 字节恒 `0`、`total` 恒等于 `count`；
   ③ 相邻两条的**首字节**间隔 ≤2500ms。→ 一次通过就说明 §3 与 §5.1 都成立。
   同时我方应每帧回一条 `0x82`（有就够，视觉不必处理）。
3. **按 PA0 走一件**：确认 `0x42→0xC2`（版本字节 `0x02`）、随后 `0x44` 四要素显示、
   视觉回 `0xC4` **之后**机械臂才起动下一件。→ 锁步成立。

第 2 步是这次改动的全部风险所在；它过了，后面就是坐标标定与识别率的问题，不是协议问题。
