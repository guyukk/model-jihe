## 🧪 串口测试流程

使用串口助手向MaixCAM2发送以下十六进制数据进行测试。

### 测试准备

- **串口**: `/dev/ttyS4`
- **波特率**: 115200
- **格式**: 8N1
- **发送格式**: 十六进制 (HEX)

---

### 步骤1: 系统启动 (SYS_START)

**发送数据**:
```
AA 55 02 42 01 01 02 1E
```

**说明**:
- `AA 55`: 帧头
- `02`: payload长度
- `42`: SYS_START命令
- `01`: SEQ序号
- `01 02`: mode=1, proto_ver=0x02
- `1E`: CRC8校验

**期望响应** (0xC2):
```
AA 55 02 C2 01 00 02 3A
```
- `00`: R_OK (成功)
- `02`: 协议版本0x02

**控制台输出**:
```
收到SYS_START: mode=1, proto_ver=0x02
✓ 系统启动确认，进入READY状态
```

---

### 步骤2: 扫描请求 (SCAN_REQ)

**发送数据**:
```
AA 55 02 43 02 01 00 BB
```

**说明**:
- `43`: SCAN_REQ命令
- `02`: SEQ序号
- `01 00`: reason=1 (首次扫描), rsv=0
- `BB`: CRC8校验

**期望响应** (0x02 SCAN_RESULT):

假设检测到2件物料，响应示例：
```
AA 55 18 02 02 01 02 00 02
01 05 01 00 B0 04 20 03 5A 00
06 03 00 00 0C FE FA 00 FF FF
08
```

**响应格式**:
- `02`: SCAN_RESULT命令
- `02`: SEQ (回显)
- `01 02 00 02`: reason=1, total=2, batch=0, count=2
- 后面是2个piece结构体 (每个10字节)

**控制台输出**:
```
收到SCAN_REQ: reason=1
✓ 发送扫描结果: 2件物料
```

---

### 步骤3: 分拣上报 (PICK_REPORT)

**发送数据**:
```
AA 55 06 44 07 01 01 05 00 03 00 31
```

**说明**:
- `44`: PICK_REPORT命令
- `07`: SEQ序号
- `01`: seq_no=1 (序号)
- `01`: shape=1 (圆形/cone)
- `05`: color=5 (蓝色)
- `00`: result=0 (R_OK成功)
- `03 00`: total_ok=3 (累计3件，小端)
- `31`: CRC8校验

**MaixCAM2行为**:
1. 在屏幕显示四要素：
   ```
   序号: 1
   圆形 蓝色
   ✓ 成功
   累计: 3
   ```
2. 显示500ms后发送应答

**期望响应** (0xC4):
```
AA 55 01 C4 07 00 86
```
- `C4`: PICK_REPORT应答
- `07`: SEQ (回显)
- `00`: R_OK

**控制台输出**:
```
收到PICK_REPORT: 序号=1, 形状=1, 颜色=5, 结果=0, 累计=3
✓ 已显示并应答PICK_REPORT #1
```

---

### 步骤4: PING测试 (可选)

**发送数据**:
```
AA 55 04 4F 10 DE AD BE EF D5
```

**说明**:
- `4F`: PING命令
- `10`: SEQ
- `DE AD BE EF`: 测试数据 (4字节)

**期望响应** (0xCF):
```
AA 55 04 CF 10 DE AD BE EF 39
```
- 原样回显测试数据

---

### 步骤5: 心跳监测

**观察心跳**:

MaixCAM2每250ms自动发送心跳 (0x01):
```
AA 55 03 01 XX YY 00 00 ZZ
```
- `XX`: SEQ (递增)
- `YY`: state状态码
- `ZZ`: CRC8

**状态码对照**:
| 值 | 状态 |
|----|------|
| 0 | INIT |
| 1 | READY |
| 2 | SCANNING |
| 3 | PICKING |
| 4 | DISPLAYING |

你也可以向MaixCAM2发送MCU心跳 (0x41)，保持链路：
```
AA 55 03 41 01 01 00 00 FF
```

## 📍 坐标系统

模型检测得到 ROI 归一化坐标 `(norm_x, norm_y)` 后，先换算为 ROI 局部坐标，
再按机械坐标标定执行轴互换及原点平移。所有坐标单位均为 **0.1mm**：

```text
ROI局部X = norm_x × 1600
ROI局部Y = norm_y × 1600
机械X = ROI局部X - 800 + 600
机械Y = ROI局部Y - 800 + 1400
```

局部坐标先四舍五入到整数（0.1mm单位）。
原有映射先将视觉 Y/X 交叉映射为 ROI 局部机械 X/Y；新的规则将这两个坐标再互换，
因此最终公式直接使用 ROI 局部 X/Y。ROI 中点 `(800, 800)` 对应实际机械坐标 `(600, 1400)`。
例如，旧映射得到 ROI 坐标 `(1126, 510)` 时，先互换为 `(510, 1126)`，
再平移得到实际机械坐标 `(310, 1726)`。

ROI 边界对应的机械坐标范围为 X=`-200..1400`、Y=`600..2200`（0.1mm）；
坐标按标定原点换算，不会额外钳位到 `0..1600`。

## 🔧 标定工具

### ROI标定

```bash
python calibrate_roi_serial.py
```

**串口命令**:
- `U/D/L/R`: 移动ROI位置
- `W/S/A/E`: 调整ROI大小
- `Z`: 重置
- `Q`: 保存并退出

### HSV颜色标定

```bash
python calibrate_hsv_v3.py
```

**操作步骤**:
1. 发送 `1/2/3/4` 选择颜色
2. 将色块放在画面中心（绿色十字准星）
3. 发送 `G` 一键采样
4. 发送 `P` 保存，`O` 退出

标定完成后，将结果更新到 `config.py`。

## 🐛 调试技巧

### 查看状态

画面左上角实时显示：
- **状态**: INIT → READY → SCANNING → DISPLAYING
- **链路**: LINK (绿色) / DISC (红色)

### 日志输出

```
✓ 系统启动确认，进入READY状态
收到SCAN_REQ: reason=1
✓ 发送扫描结果: 3件物料
收到PICK_REPORT: 序号=1, 形状=2, 颜色=5, 结果=0, 累计=1
✓ 已显示并应答PICK_REPORT #1
⚠ 链路中断！
```

### 常见问题

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 链路显示DISC | 未收到MCU心跳 | 检查串口连接，发送心跳0x41 |
| 颜色识别错误 | HSV阈值不准 | 重新标定HSV |
| 坐标偏差 | ROI或转换参数错误 | 重新标定ROI，检查COORD_SCALE_FACTOR |
| CRC错误 | 数据传输错误 | 检查波特率、连线质量 |

```

        ├── model_9338_npu.axmodel   ✅ 必需
        └── model_9338_vnpu.axmodel  ✅ 必需
```

新模型类别为 `cone`、`cube`、`pyramid`、`5edge`。串口形状 ID `0x04` 现表示五棱柱（原长方形定义已调整），MCU 端需同步采用此映射。应用 ID 保持为 `cone_cube_pyramid`，用于更新原应用。

主程序会读取标定工具保存的 `/root/roi_config.json`；如果设备上没有该文件，则使用 `config.py` 中的默认 ROI。该设备文件不随应用包覆盖。

相机采集尺寸为标定基准 `320x256` 的2倍，ROI会按相同倍率缩放，因此视野中的相对检测区域不变。检测框、文字、ROI边框和跨帧匹配距离也会按倍率调整，保持显示大小和检测行为一致；更高分辨率会增加摄像头采集和颜色分析的内存/计算开销。
